Connectors

阅读约 6 分钟·核对日期 2026-10-20
事实来源

docs.x.ai/grok-bot/computer-and-apps · docs.x.ai/grok-bot/settings-and-notifications · docs.x.ai/grok-bot/troubleshooting · docs.x.ai/grok-bot/chat-and-collaboration

连接器给 Bot 一条访问外部服务的结构化通道，以插件形式装在侧边栏的 Connect apps 里。装好之后，对话里用 @ 挂到本次任务，比纯点网页更稳。

1. 安装一个连接器

  1. 从侧边栏打开 Connect apps。
  2. 浏览可用插件，找到你要的服务。
  3. 选 Add。
  4. 需要时在浏览器里完成身份验证，再回到 Grok Bot。
  5. 打开对话，输入 @ 把连接器挂到这次任务上；输入 / 可以引用已保存的技能。

已安装的连接器按账号生效，不是某一个 Bot 私有。某个 Bot 要用它，通常还要有对应登录或权限。插件不在 Settings 里管理，入口始终是 Connect apps（界面常见中文 连接应用）。Settings 管的是主题、Auto-review、本机执行等；要装 / 卸插件，回到侧边栏。

查看已装列表：在 Connect apps 里打开 Your plugins；Manage plugins and skills 下列出 Installed 插件与 Private skills。

上图可见：顶部搜索「在应用和技能中搜索」、已连接 N 个 入口、分类标签（全部 / 密码管理器 / 效率 / 通信 / 设计 / 代码等）、为你推荐 列表里每项旁的 添加，以及部分服务上的 连接。装好后回到对话用 @ 挂接。

2. 优先用连接器，再考虑浏览器

官方建议：有连接器时优先用连接器。它通常比在网页上点来点去更可靠，也更容易留下可审计的调用记录。

没有连接器的服务，或者连接器盖不住的可视流程（布局确认、拖拽、验证码前后的人工步），再用云电脑上的浏览器。同一原则也适用于情报采集、写 Notion、发草稿：能走插件就走插件。

把连接器挂进任务
@Notion 把下面三条收藏整理进「选题库」数据库，每条写标题、一句话理由、原文链接。不要发布，写完停下来给我看。

3. X 的特殊之处

不连接 X 账号，Bot 也能搜索并阅读 X 上的公开内容：检索帖子、从链接打开帖子、读某个账号的帖子与提及、查看引用与转发、统计某个话题近期的帖子数量、查趋势与新闻。这种访问是只读的，不代表你登录。

要读私信、收藏、首页时间线或点赞列表，需要从 Connect apps 安装 X 插件并登录。做「每日情报」这类要读首页时间线的任务，必须先装好 X 插件。

4. 授权失败或掉线时

  1. 打开 Connect apps → Your plugins，确认插件列在 Installed。
  2. 打开插件详情页，重新走一遍身份验证（有的服务显示 连接 / 重新授权）。
  3. 若授权已在源服务里被撤销，先删掉插件再重连。
  4. 仍然失败时，换一个任务做最小复现（只读一条记录），把报错原文留给支持或论坛帖。
  5. 重装之后，检查依赖该连接器的例程：旧授权失效时，例程会空转或报错——先 Test run 再重新启用。

组织账号下，可用连接器可能受 Cursor Team Marketplace 与管理员策略限制。个人账号看不到某个插件时，先确认套餐与地区是否支持，再查官方更新说明。本站不写具体套餐名单。

授权成功但任务仍失败时：确认对话里是否用 @ 显式挂了该连接器；有些流程需要你点名，Bot 才优先走插件而不是浏览器。

5. 和技能、例程、渠道的关系

连接器解决「连到哪个系统」；技能解决「怎么做」；例程解决「什么时候做」。外发类连接器（邮件、Slack）装好后，仍应先出草稿卡再等人点发送——见Channels（渠道）。

建议顺序：先装连接器并跑通一次手动任务 → 再存技能 → 最后才定例程。顺序反了，例程很容易在缺权限时空转。

6. 常见第一批连接器怎么选

不同账号能看到的插件列表可能不同，按意图选：

  • 知识与笔记：把搜集结果写入结构化库，任务里写清库名与字段。
  • 邮件与协作：优先出草稿，发送必须审批；手机上也有邮件 / Slack 草稿入口。
  • 代码托管：开 PR、读 issue 前写清仓库与分支；合并仍应等人确认。
  • 浏览器保底：没有插件时，让 Bot 说明将访问的站点；敏感登录用 Take over。

装之前先问：只读是否够用？只读任务不要开写入权限。

只读探路
先不要改任何数据。用已连接的工具列出我有权访问的对象名称（最多 10 个），
用表格回我：名称、用途猜测、完成「汇总本周更新」是否必须写入。

7. 和实践场景的衔接

把「平台和博主列表」交给 Bot 做情报、把收藏写进选题库，背后都是连接器或浏览器。复现时先完成创建第一个窄职责 Bot的五要素首单，再装连接器，最后才定例程——顺序反了最容易空转。

你要检查什么

  • 任务里是否用 @ 显式挂了需要的连接器。
  • 该只读的任务有没有误要写入权限。
  • X 场景：公开搜索是否够用，还是必须登录插件。
  • 重装插件后，旧例程是否还指向已失效的授权。
  • 是否误在 Settings 里找插件——入口是 Connect apps。

常见坑

  • 装了插件却从不 @，任务一直走脆弱的网页点击。
  • 例程先于连接器上线，天天报授权错误。
  • 把「已连接」当成「可以自动群发」——外发仍要草稿 + 人点发送。
  • 源站撤权后只在 Grok Bot 侧重装，忘了两边对齐。
  • 只读任务却申请了写入权限。
